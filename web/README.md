# `web/` — the classical baseline, portable

Two files that let the [ADR-017](../decisions/017-classical-baseline-bakeoff.md)
classical baseline run in a browser tab with no server, no build step and no
dependencies:

| File | What it is |
|---|---|
| `baseline_export.json` | The fitted model as data: vocabulary, idf vector, per-axis coefficients + intercepts, class order, the vectorizer config it was fitted with, and the sklearn stop-word list. Generated by `scripts/export_baseline.py`. |
| `baseline_infer.js` | A dependency-free ES module that reproduces scikit-learn's transform + `decision_function` over that JSON. |

**This is a portability artifact, not a new measurement.** The baseline's accuracy
is the frozen record in [`evals/baseline_eval.txt`](../evals/baseline_eval.txt)
(category 72.2%, operational_domain 66.7% against the 54-row human gold set) and
this export reproduces that same fit — it does not restate, recompute or improve
those numbers. `region` is not covered; the baseline never had region labels to
train on.

## Using it

```js
import { classify, prepare } from "./baseline_infer.js";

const model = await fetch("./baseline_export.json").then((r) => r.json());
const ctx = prepare(model);          // do this once
const out = classify("Army awards $9.8B contract for readiness", ctx);
// out.category            -> { label, scores, probabilities }
// out.operational_domain  -> { label, scores, probabilities }
```

- `prepare(model)` is optional — `classify(text, model)` works too, but it rebuilds
  the stop-word set and token regex on every call. Prepare once if you classify as
  the user types.
- `scores` are raw `decision_function` values; `probabilities` are their softmax,
  which is exactly `predict_proba` for this multinomial fit. Show whichever reads
  better; the label is `argmax` of either.
- A document containing no known vocabulary term normalises to the zero vector, so
  the prediction falls out of the intercepts alone. That is sklearn's behaviour, not
  a bug, but a consumer may want to say "no signal" instead of showing a confident-
  looking label.
- The JSON is ~583 KB raw and ~208 KB gzipped. Serve it compressed; every static
  host does this by default. Fetch it once and cache the parsed object.

## Consuming it from another repo

Prefer **vendoring a copy** (commit both files into the consuming repo) over
hot-linking. The pair is versioned together — `baseline_infer.js` reads the config
echoed inside `baseline_export.json` — and a page that fetches one from a moving
`main` while holding the other is the exact mismatch the parity gate exists to
prevent. `raw.githubusercontent.com` also serves with `Content-Type: text/plain`
and no long-lived caching, which is the wrong shape for a module import.

If you do link rather than vendor, pin a tag or commit SHA, never `main`:

```
https://raw.githubusercontent.com/sanlee-ys/defense-news-classifier/<sha>/web/baseline_export.json
https://raw.githubusercontent.com/sanlee-ys/defense-news-classifier/<sha>/web/baseline_infer.js
```

## Regenerating

```bash
uv run python scripts/export_baseline.py            # rewrites baseline_export.json
uv run python scripts/generate_parity_fixture.py    # rewrites tests/fixtures/baseline_parity.json
node scripts/parity_check.mjs                       # the gate CI runs
```

Run all three in that order — the fixture records the export's training-content
hash, and the check refuses to compare a fixture and an export that disagree on it.
`scripts/export_baseline.py --max-features N` caps the vocabulary if the artifact
ever needs to be smaller; the cap is recorded in the JSON's metadata, and it costs
real accuracy (capping to 1300 terms dropped operational_domain from 66.7% to 61.1%
on the gold set), so it is opt-in.
