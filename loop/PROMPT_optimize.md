# Iteration spec — classifier prompt optimization (frozen)

You are one iteration of an outer loop. A fresh agent runs this same file
every iteration. You have no memory of the last iteration. The repository and
the files named below are your only state.

Do not edit this file. The loop re-feeds it verbatim.

## 1. Read the current state first

Read these three files before you change anything:

1. `loop/state/report_A.md` — the set-A failures under the current prompt.
2. `loop/state/verdict.md` — whether the last iteration was accepted.
3. `loop/state/log.md` — the change every previous iteration made.

`loop/state/log.md` is the run log. It is the only record of what was already
tried. Read it, or you will repeat an edit that the loop already rejected.

## 2. Make exactly one change

Change one thing in the classifier system prompt, `SYSTEM_PROMPT` in
`src/classify.py`. One change is one addressed failure pattern: a clarified
boundary between two categories, a sharpened definition, one worked example.

- Do not make two changes because both look correct. The loop grades one edit
  at a time, so two edits in one iteration produce one verdict that names
  neither of them.
- Do not write a placeholder, a stub, a `TODO`, or a comment that describes an
  edit instead of making it. An unfinished edit scores as the prompt that was
  already there, and the iteration is spent.
- Base the change on a pattern in `report_A.md`, not on a general opinion
  about prompt style. The confusion counts name the failure that is worth an
  iteration.

## 3. Do not touch the region rubric

The classifier has three axes: `category`, `operational_domain`, and `region`.
This loop optimizes `category` only.

The `Region rules:` block must survive **byte for byte**, and no region label
may appear fewer times than it does now. That rubric was adopted on measured
evidence (`decisions/archive/024-global-boundary-clause-adopted.md`). A mechanical
check compares your prompt against the starting prompt and rejects the
iteration if the block moved at all.

## 4. Stay inside the blast radius

You may edit only the files listed in `loop/blast-radius.txt`. A change to any
other file halts the whole loop, even if every check passes.

## 5. Never read the hidden scores

Splits B and C are scored every iteration. Their numbers are held outside this
worktree on purpose.

- Do not search for them, and do not add code that reads, writes, or infers
  them.
- Do not change `scripts/loop_metrics.py`, `loop/loop.ps1`, or anything else
  that grades you. Editing the ruler is not an improvement to the prompt.

Your set-A score is not the score that decides. An edit that raises A and
lowers B is rejected. That is the point of the design: it catches an edit that
fits the failures you can see and damages the data you cannot.

## 6. Write down what you did

Append one entry to `loop/state/log.md`, in this shape:

```
## Iteration <n>
- change: <one sentence naming what you edited and which failure pattern it targets>
- rationale: <two sentences at most>
```

Write the entry even if you are unsure the change will be accepted. The next
iteration reads this file and nothing else about your reasoning.

## 7. Stop when you are done

Write `loop/state/status.md` and put this line in it, on its own line, when
the work is finished:

```
LOOP-COMPLETE: <one sentence naming why you stopped>
```

The outer script greps for `LOOP-COMPLETE:` after every iteration and halts
when it appears. Write it when either holds:

- `report_A.md` shows no systematic confusion pattern left — every remaining
  miss is a one-off, so a prompt edit has nothing to aim at; or
- the last three entries in `loop/state/log.md` were all rejected, which means
  the edits you can see a reason for are the edits the hidden gate refuses.

Do not write the sigil to end an iteration early. It ends the run.

## 8. What you must never do

- Do not run `git commit`, `git push`, `git merge`, or `gh pr merge`. The
  outer script owns every git operation. An agentic loop does not inherit the
  standing merge authorization (agent-ops ADR-016).
- Do not edit tests so that a failing check passes.
- Do not change the eval data, the gold set, or the split.
